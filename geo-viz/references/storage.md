# 存储与缓存（本地优先，服务端可共享）

## 单作品原则

1. 只取本片需要的 bbox / 城市 / 路线 / zoom/LOD。
2. 数据放在作品目录：Remotion `works/<id>/geo/`；HyperFrames `assets/geo/`。
3. 每份数据写入 manifest，记录来源、版本/日期、许可、CRS、范围、分辨率、垂直基准和署名。
4. 技能包只带说明，不附带全球 DEM、OSM、行星纹理或瓦片仓库。
5. 命中缓存就复用；文件损坏、版本过期或覆盖范围不足时才补取，不无故重下。

## 资源解析顺序

```text
需要资源 K
  → 当前作品 geo/ 命中且校验通过？直接用
  → 本机共享缓存命中？复制/链接到作品 geo/ 后用
  → 宿主服务端共享缓存命中？取获准的版本化资产
  → 均未命中：按 data.md 从允许的数据源获取所需范围
      → 预处理（裁切、投影、简化、路线平滑）
      → 写入作品 geo/ 与 manifest
      → 按宿主策略回填共享缓存
  → 下载失败：停止该镜，报告缺失数据；不得用残缺瓦片或假地理代替
```

## 大规模部署（可选宿主能力）

面向大量用户/大量重复地区请求时，不能把每个生成任务都变成一次公共数据服务爬取。宿主可以提供共享只读资产层：

- 对象存储或等价存储保存区域 PMTiles、DEM、矢量提取物和纹理；通过 CDN/边缘缓存分发。
- 资产按数据集版本、区域/bbox、zoom/LOD、CRS、处理参数建立稳定键；不同许可的数据分开管理。
- 生成任务在 worker 本地做短期缓存；同一数据集在用户间复用，不重复从上游下载。
- 设置并发限制、队列、缓存命中统计、重试退避、来源熔断、配额和过期清理。
- 仅缓存许可允许缓存和再分发的资产；公共服务可访问不等于允许平台批量复制/再分发。
- 以上是平台扩展模式，不绑定某个云厂商或用户上传 API；基础技能仍可独立在单机工作。

## 不要做的事

- 预先镜像整个地球“以防万一”。
- 把全球原始数据打进技能包或 npm 包。
- 强制每个安装者写入某家云目录。
- 自动拆分公共服务请求、轮换身份或代理以规避额度/服务条款。
- 将未核验来源和许可证的数据写入共享缓存。
